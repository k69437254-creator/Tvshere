# حسوني Tv — 1.1.0 Release Candidate

تطبيق Android لالتقاط إشارة كارت HDMI المتصل عبر USB-OTG، ومعاينتها، ثم ترميزها وإرسالها إلى خادم RTMP/RTMPS.

## ما تم ربطه في هذا الإصدار

- مصدر UVC واحد يديره `UvcVideoSource` ويغذي معاينة RootEncoder ومخرج الترميز من المسار نفسه؛ لا يفتح التطبيق كاميرا UVC ثانية عند بدء البث.
- محرك RootEncoder 2.8.1 لإعداد مرمّز الفيديو والصوت وإرسال RTMP/RTMPS.
- إدخال صوت USB/UAC باستخدام `AudioRecord` مع تحديد جهاز USB المفضل. لا يوجد رجوع تلقائي إلى ميكروفون الهاتف.
- كتم الصوت والتحكم بمستوى PCM.
- طبقات الشعار والنتيجة والشريط النصي تُرسم في Bitmap شفاف وتُركّب بمرشح OpenGL في مسار المعاينة والترميز.
- إعداد الدقة ومعدل الإطارات ومعدل البت، مع خفض/رفع تدريجي لمعدل البت عند رصد ازدحام مرسل RTMP أو زيادة الإطارات المفقودة.
- خدمة أمامية وإشعار دائم وقفل CPU جزئي أثناء البث لتقليل توقف الإرسال عند إطفاء الشاشة أو انتقال التطبيق للخلفية ضمن قيود Android.
- إحصائيات حقيقية متاحة من مرسل RootEncoder: معدل إرسال البث، إطارات الفيديو والصوت المرسلة، حجم البيانات المرسلة، وإطارات الفيديو المفقودة، إضافة إلى CPU وذاكرة التطبيق RAM وحرارة البطارية. لا يعرض التطبيق عدد مشاهدين وهميًا.
- اختبارات وحدات لـ AudioMixer ومتحكم معدل البت، وفحص بنية إصدار قبل بناء APK في GitHub Actions.

## بيانات البث

اختر Telegram أو TikTok أو خادمًا مخصصًا، ثم ألصق **رابط الخادم ومفتاح البث الخاصين بجلسة البث الحالية**. بعض المنصات تصدر رابطًا ومفتاحًا متغيرين لكل جلسة؛ لذلك لا يوجد عنوان خادم أو مفتاح ثابت مضمّن في التطبيق. يجب أن يبدأ رابط الخادم بـ `rtmp://` أو `rtmps://`. استخدم `rtmps://` متى كان متاحًا؛ RTMP العادي غير مشفّر أثناء النقل، وقد فعّل التطبيق cleartext traffic للسماح به.

لا يتصل التطبيق بواجهات Telegram أو TikTok لإصدار مفاتيح الجلسات ولا يتجاوز أهلية الحساب أو قيود المنصة. هو مرسل RTMP/RTMPS عام يستخدم بيانات الإدخال التي يوفرها المستخدم.

## الصوت عبر HDMI — قيد يعتمد على كارت الالتقاط والهاتف

يلزم أن يعرّف كارت الالتقاط مدخل USB Audio Class (UAC) وأن يعرضه Android ضمن أجهزة الإدخال. يوجّه التطبيق `AudioRecord` إلى جهاز USB المكتشف فقط. إذا كان الكارت يمرّر الصوت داخل واجهة UVC غير المدعومة كمدخل UAC، أو لم يعرض Android مدخل الصوت، فسيظهر أن الصوت غير متاح وسيستمر إرسال الفيديو فقط؛ لا يستطيع التطبيق استخراج صوت غير مكشوف من برنامج تشغيل الجهاز.

## البناء الآلي

المستودع المستهدف: `k69437254-creator/Tvshere` — الفرع `main`.

بعد رفع المصدر، يشغّل GitHub Actions فحص المصدر، واختبارات الوحدات، ثم `:app:assembleDebug`. عند النجاح ستجد Artifact باسم `HassouniTv-1.1.0-rc1-debug-apk` يحتوي على `app-debug.apk`.

## الرفع عبر Termux

1. فك ضغط ملف الإصدار مباشرة داخل مجلد استنساخ المستودع، مثل `~/Tvshere`، مع السماح باستبدال الملفات.
2. افتح Termux وانتقل إلى `~/Tvshere`.
3. نفّذ: `bash TVSHERE_PUSH_TERMUX.sh`.
4. راجع قائمة الملفات التي سيضيفها السكربت وأكد عملية الرفع. السكربت لا يستخدم `force push` ولا يحذف المستودع أو بيانات Git.

السكربت يدعم المستودع الفارغ: ينشئ أول commit ثم يرفع الفرع `main`. إن كان الفرع يحتوي تاريخًا بالفعل، يستخدم push عاديًا ويرفض تعارضات التاريخ بدل تجاوزها. افتراضيًا لا يحاول البناء داخل Termux؛ GitHub Actions ينفّذ البناء بعد الرفع. بعد تثبيت Gradle وAndroid SDK محليًا يمكنك طلب البناء المحلي قبل الرفع باستخدام `TVSHERE_BUILD_LOCAL=1 bash TVSHERE_PUSH_TERMUX.sh`.

## اختبار الهاتف بعد نجاح البناء

1. ثبت APK على هاتف Android 7 أو أحدث، وامنح إذن الكاميرا.
2. أوصل مصدر HDMI غير محمي، واضبطه مبدئيًا على 1080p/30، ثم أوصل كارت UVC عبر USB-OTG مع طاقة كافية.
3. وافق على نافذة إذن USB. يجب أن تظهر معاينة الإشارة وحالة الاتصال. عند فشل التعرف أو التفاوض على الوضع استخدم زر «إعادة فحص كارت الالتقاط» بعد التحقق من طاقة OTG ودقة المصدر.
4. تحقق من ظهور مدخل صوت USB في بطاقة الصوت. اسمح بإذن تسجيل الصوت عند بدء البث.
5. ألصق عنوان الخادم ومفتاح بث تجريبيين، وابدأ الإرسال. تحقق من وصول الفيديو والصوت في الوجهة، ثم اختبر الإيقاف وإعادة الاتصال وفصل الكارت أثناء التشغيل.
6. جرّب إطفاء الشاشة والعودة للتطبيق، ثم اختبر طبقة الشعار والنتيجة والشريط النصي.

## ما لا يمكن إثباته دون جهازك وحساب البث

نجاح فحص المصدر أو بناء APK لا يثبت توافق كارت HDMI المحدد مع الهاتف، أو ظهور صوت UAC منه، أو قبول خادم البث لمفتاح الجلسة. يجب اختبار هذه الحالات فعليًا على جهازك. كما أن Android قد ينهي الخدمة بسبب قيود النظام أو الإغلاق القسري؛ لا يوجد ضمان للاستمرار بعد Force Stop.
